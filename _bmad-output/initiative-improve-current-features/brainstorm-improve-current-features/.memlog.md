- (decision) Affinity clusters (10): A Reliability guardrails (tests, CI on PRs, logging, diagnostics); B Capture-to-share speed (overlay one-key actions, quick-access thumbnail, re-edit last, skip-editor modifier); C Safe sharing/redaction; D Editor power (hand zoom, boundary, presets, eyedropper, storyboard, snapping); E Recording for explaining (markers, keystrokes, presets, replay buffer, webcam); F History as a library (OCR search, metadata, cleanup, thumbnail cache); G Bring images in/automation (open image, clipboard, Services, URL scheme, CLI); H Presenter mode; I Language (translate, OCR langs); J Integrations (Jira, Markdown, ticket prefix)
- (decision) Scope rule: the initiative improves existing features; net-new capabilities (Jira upload, webcam, scrolling capture, cloud share, on-device AI, CLI/URL scheme) are Won't-this-time
- (decision) MUST 1 Reliability guardrails: swiftc test runner, coordinate math extracted + multi-monitor geometry self-test, gap-model layout check, CI build on every PR, os.Logger instead of print — most recent fixes are regressions in overlay/editor/multi-monitor, and Musts 2-3 edit exactly those files
- (decision) MUST 2 Capture-to-share speed: one-key C/S/P actions from the overlay, quick-access thumbnail after capture, re-edit last capture, hold-shift to skip the editor once — the daily path, extends CaptureBehavior rather than adding architecture
- (decision) MUST 3 Safer redaction: solid redact bar alongside blur/pixelate, plus one-click auto-detect of emails/tokens/IBANs/phones via the existing TextRecognizer — captures land in Jira/Teams at a fintech
- (decision) SHOULD: editor polish from CLAUDE.md's flagged trades (display boundary while dragging knobs, option-drag hand zoom, style presets); open any image/clipboard in the editor; recording markers + keystroke overlay + purpose presets/GIF size target
- (decision) COULD: History OCR search + thumbnail cache, presenter mode, eyedropper/contrast, translate, pin opacity/click-through, pseudo-localization layout check, per-app post-capture behaviour
- (insight) The frozen still is the platform: one-key actions, quick-annotate, screen ruler, colour picker and auto-redact all run on the freeze begin() already takes — no new capture path. One OCR pass at capture time feeds three clusters (redaction, copy-text mode, History search): build it once, store it, reuse. Reliability first is not overhead — Musts 2 and 3 modify SelectionOverlay/EditorWindow/CanvasView, the highest-churn files. CaptureBehavior already routes editor/save/clipboard, so one-key actions and per-app behaviour extend it. Recommended initiative: 3 epics in order — Guardrails, Capture-to-share, Safer redaction; Shoulds become a follow-up epic
